## [0.2.0] - 2026-10-27

The live availability check moves into the gem. In 0.1 it was a generator that copied a controller, a route, a Stimulus controller and a partial into every app, each yours to keep in step with the gem; now the engine ships all of it, and in an app on the conventional importmap + Stimulus setup a username field that checks names as people type is four lines: `gem "usernames"`, `has_username :handle`, `<%= f.username_field :handle %> <%= f.username_status :handle %>` and `import "usernames"` — with no copied username implementation left in the app. `has_username` also learns three options that apps were writing by hand around it.

### Added

- **The availability endpoint**, `Usernames::AvailabilityController`, at `GET /usernames/availability?username=…&target=…`, answering `{ state: "free" | "taken" | "invalid", message: }` in the model's own words. The guard rails of the 0.1 template come with it: Rails' `rate_limit` (`config.availability.rate_limit`), taken, reserved and disallowed names answered alike as "taken", the server's own normaliser first, and `Cache-Control: no-store` on every answer — 404s, 429s and 503s included.
- **Targets: an explicit allowlist** of what the endpoint answers for, `config.availability.targets = { "user" => "User#handle" }`, which the installer writes. A request names an alias; only a configured alias is looked up, and the class it names is resolved from your configuration on every request — never from what a client sent — so declaring `has_username` on a model never publishes it. An unknown alias is a 404 (rate limited like any request); a configured one that no longer resolves raises `Usernames::ConfigurationError` instead of answering.
- **A route drawn by the engine**, appended after yours as `usernames_availability` at `config.availability.path` (`nil` draws none), without a format, and skipped when you draw one of that name yourself. `usernames_availability` is also a routing method, for putting it above a catch-all such as `get "*path"`, which would otherwise swallow it. Its first segment is reserved like any of your routes.
- **Form helpers.** `f.username_field :handle` renders the input with the `username-check` controller on it — the rules (messages in the model's words), the case mode, the saved name and the endpoint — and `f.username_status :handle` the `<output aria-live="polite">` it writes to. `availability: false` keeps the format hints without a request; `static: true` is a plain field. `class`, `data-controller`, `data-action` and `aria-describedby` join the field's own; ids follow `field_id`, namespaces and indexes included. A field for a column no target names raises in development and test, and renders plain (logged once) in production.
- **JavaScript shipped by the gem**, in `app/assets/javascripts/usernames/`: the Stimulus controller, and `index.js`, which registers it on stimulus-rails' exported `application` — deterministically, once. With importmap-rails the engine pins `usernames` and `usernames/username-check` (before importmap draws its map); Propshaft and Sprockets serve both files, and Sprockets is told to precompile them. Without importmap-rails, or without an asset pipeline, the engine adds nothing. The controller shows `checking`, `free`, `taken`, `invalid`, `unchanged` or `error` in the status's `data-state`; a request generation counter and aborts make sure only the latest answer is shown (A, then B, then A again included), a 429, 503, network failure or unreadable answer ends in `error` with a localised message (`usernames.availability.error`, in English, Spanish and Portuguese), and the status resets on disconnect, on form reset and before Turbo caches the page. It still never blocks submission.
- **`required: { on: :profile }`** asks for a name whenever the record is validated in that context (or one of several), on every save there — including an account whose name was blank before the gem arrived, since that form is where they type one. Outside it, nothing changes.
- **`seed: :first_name`** (or a proc): a generated name starts from that value — `ana`, then `ana_42`, then the default shape when it is blank or every form of it is taken. It is read once per save and reused by a redraw after a lost race; an error raised in it is the app's.
- **`clearable: false`** refuses saving a saved name blank again (`:blank`), required or not. It is not immutability, leaves stored blanks alone, and — being a validation — is skipped by `update_column` and `update_all`.
- **`config.availability.parent_controller`** (default: your `ApplicationController` when there is one, so its locale and authentication callbacks apply; `"ActionController::API"` works) and **`config.availability.rate_limit_store`** (default `Rails.cache`, read once when the endpoint's class loads).
- **`rails generate usernames:javascript`** copies the Stimulus controller into `app/javascript/controllers` for apps that bundle their JavaScript, where `import "usernames"` has nothing to resolve it.

### Changed

- **`rails generate usernames:install`** writes `config.availability.targets` for its `--model`/`--column`, and in an importmap app whose `controllers/application.js` exports the Stimulus application it appends `import "usernames"` to `app/javascript/application.js` — once, never removing anything — saying why not otherwise. It ends with the form line, the Devise strong-parameters line and the production cache store.
- **`rails generate usernames:availability`** no longer copies anything by default: it explains that the check is built in, and lists the files a 0.1 install copied, with the two ways to upgrade. `--copy` writes a set of your own — the endpoint (replacing the gem's, same class), the Stimulus controller, a partial built on the helpers, and the route at the top of `config/routes.rb` — all speaking the same protocol.
- **A rate limit store that can't count is a 503 everywhere but development and test.** 0.1 answered 503 only in production and only for a `NullStore`; the endpoint now notices any store whose `increment` returns nothing or fails (a cache whose backend is down, a wrapper around a `NullStore`), and refuses in staging too. In development and test it proceeds unlimited and logs once.

### Fixed

- **A new record saved in a validation context of its own got no generated name.** Generation ran `on: :create`, which an explicit context (`save(context: :import)`) replaces, so such records were saved without one. It now runs for every new record whose name is blank, whatever the context.

### Upgrading from 0.1

Nothing changes for a model with `has_username` and no availability check. If you ran `rails generate usernames:availability` under 0.1:

- **Your copied files speak the 0.1 protocol, and they win over the gem's.** Your controller reads `params[:<column>]` and asks `current_user`; the gem's helpers send `username` and `target`. Pick one mode — `rails generate usernames:availability` lists what it finds. *Managed* (recommended): delete the controller, the `usernames/availability` route, `app/javascript/controllers/username_check_controller.js` and `app/views/usernames/_field.html.erb`; add `config.availability.targets = { "user" => "User#username" }`, replace the partial with `f.username_field` / `f.username_status`, and add `import "usernames"`. *Customized*: keep your pair, set `config.availability.path = nil`, and don't `import "usernames"` (both would register `username-check`).
- **"Already your name" is the browser's call now.** The endpoint no longer asks who is signed in: the field carries the record's saved name and shows `unchanged` without asking. A server-side `current_user` check in a copied controller is yours to keep or drop.
- **Staging needs a cache store that counts.** See *Changed*: a `NullStore` there now turns the endpoint off (503) rather than letting it run unlimited.
- **Devise drops fields it doesn't know.** If people choose their name at sign-up, permit it: `devise_parameter_sanitizer.permit(:sign_up, keys: [:handle])` and `:account_update`.
- **New locale key** `usernames.availability.error`: an app that translates the gem's messages into a language the gem doesn't ship falls back to English for it until translated.
- **A new record saved with a custom validation context now gets a generated name** (see *Fixed*). If you relied on it staying blank, pass `generate: false` or a condition.
- `clearable:` defaults to `true`: names can still be cleared, as in 0.1. Pass `clearable: false` to stop that.

## [0.1.3] - 2026-10-27

### Changed

- The gem's summary now says what it does in one line: add usernames with validations to a Rails app — block reserved names, screen profanity, enforce case-insensitive uniqueness, suggest alternatives and generate default names. No code changes; this is the first version published to RubyGems.

## [0.1.2] - 2026-10-27

### Fixed

- **The bundled lists are read as UTF-8 whatever the host's locale.** The data files were opened with Ruby's default external encoding, which is US-ASCII wherever `LANG` is unset (a cron job, a systemd unit, a bare container), and the non-ASCII entries then raised `invalid byte sequence in US-ASCII` while the gem loaded. Every read now names UTF-8; a test loads the gem under `-E US-ASCII`.

## [0.1.1] - 2026-10-27

### Fixed

- **The gemspec loads where git is missing.** Its file list came from `git ls-files`, which raised `Errno::ENOENT` wherever the git binary is absent — so a copy of the gem `git archive`d into an app's `vendor/` and loaded with `path:` crashed Bundler at boot inside a production image with no git (the app never started; nothing else was touched). The gemspec now falls back to the shipped directories (`lib/ config/ data/ sig/` and the top-level documents) when git is unavailable or the directory is not a checkout. Found dogfooding the gem in a vendored deployment; a test now loads the gemspec with an empty `PATH` and checks the fallback covers everything the built gem ships.

## [0.1.0] - 2026-10-27

First release. One line — `has_username` — gives a Rails model a username that is valid, unique, not reserved, not offensive and there from day one, with no table, no network and one unique index.

### Added

- **`has_username`** (`column = :username, required: false, generate: nil, **rules`): installs `normalizes` (so `"  @Javi_R "` is stored as `"javi_r"` and found by `where(username: "@Javi_R")`), validation **only when the value changes** (adopting the gem never breaks an existing account's other saves), presence when `required:` applies — `true`, or per record a method name or proc like Rails' `if:` (on create or when someone tries to clear it — a legacy blank still saves), uniqueness through the gem's own comparison contract, a free generated name on create when the field is blank (by default wherever a name is not required, record by record), and a race wrapper: a generated name taken by a concurrent sign-up is silently redrawn (up to three times, inside a savepoint so the surrounding transaction survives); a typed name taken by a concurrent sign-up or rename gets the ordinary `has already been taken` error (`save` → `false`, `save!` → `ActiveRecord::RecordInvalid`), never a `RecordNotUnique` 500 (lock contention between concurrent writers stays the adapter's concern: SQLite's `timeout`). Class helpers renamed with the column: `username_available?`, `suggest_usernames`, `generate_username`, `find_by_username` and `find_by_username!` (raises `ActiveRecord::RecordNotFound`); instance `username_generated?`.
- **`validates :username, username: true`** for apps that keep their own uniqueness and callbacks. Validates the attribute exactly as supplied (pair it with `normalizes :username, with: Usernames.normalizer`). Per-call rules (`username: { length: 2..15 }`), a `message:` that replaces every rule's message, and `validates_username_of`.
- **Format rules, in order, each with its own named error:** no whitespace; letters, digits and the configured separators only (default `_`; every other code point — accents, emoji, invisible and bidi characters — is refused, never stripped); length 3–30; no separator at either edge; no two separators in a row (the rule that rejects `oliver.__-hjj`); first character letter or digit; not all digits; and, when `.` is enabled, no file-extension ending (`john.json`, `x.git`, every extension Rails knows). Server regexes anchor with `\A…\z`; `Usernames.rules_for_browser` returns JavaScript-compatible sources with messages for live hints that never block submission.
- **An idempotent normaliser** (`Usernames.normalize`): UTF-8 encoding policy, NFKC, trim, lowercase (unless `case: :preserve`), and one pasted leading `@` removed as the last step. Measured idempotent on 50,000 random Unicode strings and the Big List of Naughty Strings in both case modes; never raises.
- **Reserved names** in two behaviours. *Impersonation* (~60 words plus the app's own name, read from the application class): matched on the whole name with separators and trailing digits removed and digits leet-folded, and on every segment, plus plurals — so `admin2`, `ad.min`, `adm1n_bob`, `bob.support`, `admins` are refused while `supportive`, `staffordshire`, `teamwork` and `adminbob` are not. *Exact* (~1,300): system words and placeholders (`null`, `undefined`, `deleted`, `ghost`, `everyone`, Windows device names, Unix accounts), RFC 2142 and certificate-authority mailboxes, autoconfiguration hostnames, and the union of the Big Username Blocklist, shouldbee, GitHub's, GitLab's and Gitea's route lists, django-registration and the IANA `.well-known` registry — minus company names and minus common first names. **Your routes** are reserved automatically from the router's AST and refreshed on `after_routes_loaded`. `config.reserved` (exact), `config.forbidden` (impersonation) and `config.allowed` (lift a word) extend or replace the bundled lists; `rails usernames:reserved` prints the effective set with each word's source.
- **Offensive words in severity tiers, per language** (`en` and `es` ship reviewed). Severe terms of four or more letters are matched anywhere in a name after folding leetspeak digits and separators; strong terms only as a whole name or whole segment (with `case: :preserve`, a capital after a lowercase letter separates words too: `ShitheadBob` is refused, `ScunthorpeUnited` passes); mild words are off by default. Exemptions (~800 real words and names such as `scunthorpe`, `sussex`, `cockburn`) apply to a whole name or whole segment and can never be manufactured by joining segments (`scunthorpe_united` passes; `scunt_horpe` and `f.u.c.k` do not). Hate numbers are rules, not entries: `1488`/`14_88` refused, bare `88` never, `kkk` only in English. `negro` — the Spanish word for black and a surname — is not blocked in any language. Error messages never echo the matched word. If the `moderate` gem is loaded its word list is consulted too (camelCase read as words); any callable can be an adapter, and receives the name as stored.
- **Uniqueness that uses your index.** Lowercase storage on a `"C"`-collated column (PostgreSQL) or `utf8mb4_bin` (MySQL) makes `=` bytewise, exactly as Ruby compares; `case: :preserve` keeps typed case and compares through `lower(username COLLATE "C")` on a functional unique index, with the same expression in every gem query. Rails' `uniqueness: { case_sensitive: false }` (`LOWER()`, collation-dependent, unindexable) is not used. `citext` is never used.
- **Generated names** (`quiet_otter_42`): adjective + animal + random digits from a curated vocabulary the test suite runs through the validator pair by pair; `SecureRandom` suffixes that grow on collision; `generate_username(from: "Pedro Gonzales Armillon")` → `pedro_gonzales`, cut at word boundaries, transliterated with `any_ascii` when that gem is present. Never derived from an email unless passed explicitly, and generic local parts (`info@`, `me@`) use the domain instead.
- **Suggestions** (`suggest_usernames("Javi R", count: 5)`): candidates built in memory, filtered through every rule, checked for availability in one indexed query; may return fewer than asked, never loops or raises on exhaustion.
- **Live availability check** generator (`rails g usernames:availability`): a controller, route, Stimulus controller and partial copied into the app. Rate-limited with Rails' `rate_limit` against a store captured once; refuses to run (503, logged) when that store is a `NullStore`; answers "taken" for taken, reserved and disallowed names alike; the word lists never reach the browser.
- **Generators and tasks:** `usernames:install [--model --column]` (initializer with ten options, column if missing with the right collation, the unique index; prints the adoption workflow on a populated column), `usernames:availability`, `usernames:locale --locale=fr`; `rails usernames:audit` (read-only: noncanonical rows, collision groups by comparison key, index and collation fit, values failing today's rules) and `rails usernames:reserved`. Deliberately no automatic rewriting task — renaming people silently is not a gem's job.
- **Messages in English, Spanish and Portuguese**, as standard Active Model error types (`username_reserved`, `username_edges`, `username_consecutive`, `username_digits_only`, `username_characters`, `username_not_allowed`, …) that your locale files override as usual.
- **Data provenance:** every bundled list is pinned to a source revision in `data/NOTICE` with its licence text in `data/LICENSES/`; the built gem ships both.
